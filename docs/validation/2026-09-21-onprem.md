# On-premises control standards review — 2026-09-21

Scope: all 42 registered AD, AD CS, GPO and Windows controls. Source and evaluation logic were inspected; primary sources below were retrieved on **2026-09-21**. This is a standards/implementation review, not a live on-premises assessment, certification or exhaustive exploit validation. No customer settings were changed.

**Aligned** means the narrow configuration check matches the referenced guidance, subject to stated evidence limits. **Changed** records a correction made in this review. **Needs evidence** means broader assurance needs additional collected facts or a manual verification; it is not a claim of compliance. A framework mapping denotes relevance, not implementation of every requirement in that framework.

| Control | Verdict | Basis and remaining limits | Primary source (checked 2026-09-21) |
|---|---|---|---|
| AD-PWD-001 | Changed | Default raised from 14 to 15; distinguishes single-factor NIST requirement from the 8-character MFA allowance. MFA across all AD paths is not collected. Does not prescribe periodic human-password expiry or certify blocklisting/hashing. | [NIST password requirements][nist] |
| AD-PWD-002 | Aligned | Disables reversible storage in domain/PSO policy; existing stored copies require password changes. Actual password material is intentionally not collected. | [Microsoft account assessment][accounts] |
| AD-PWD-003 | Needs evidence | 10 is a chosen baseline; 100 is a NIST upper limit, not a recommended target. Microsoft permits a zero-lockout strategy with compensating controls. Existing FAIL at zero is a product policy and must not be called universally noncompliant. Duration, attack monitoring and effective PSO membership need verification. | [Microsoft lockout trade-offs][lockout], [NIST][nist] |
| AD-KRB-001 | Aligned | 180-day KRBTGT age follows MDI. Reset procedure needs healthy replication and ticket-lifetime waiting. This service key is distinct from human-password expiry. Timestamp does not prove previous key retirement. | [MDI KRBTGT][accounts], [reset procedure][krbtgt] |
| AD-KRB-002 | Aligned | Enabled accounts without Kerberos preauthentication are flagged. No password cracking or exploit attempted. | [Microsoft account assessments][accounts] |
| AD-KRB-003 | Needs evidence | Privileged user SPNs are an exposure indicator. Missing privileged users, custom delegated privileges and group completeness need checking; absence in the collected set is not forest-wide assurance. | [Microsoft service-account assessments][accounts] |
| AD-KRB-004 | Aligned | REVIEW for ordinary user SPNs preserves legitimate service use; gMSA guidance is appropriate. Password strength, AES keys and application support are not proven by SPN metadata. | [Microsoft service-account guidance][accounts] |
| AD-DEL-001 | Aligned | Flags unconstrained delegation outside DCs; constrained delegation remains contextual and is not automatically treated as safe. | [Microsoft account assessments][accounts] |
| AD-PRIV-001 | Changed | Protected Users-only protection now requires domain evidence confirming DFL 2012 R2 or later; otherwise REVIEW. NOT_DELEGATED remains direct evidence. Non-user privileged members are excluded. | [Protected Users prerequisites][protected] |
| AD-PRIV-002 | Aligned | Stale-account review is justified; 90 days is AdminSecOps policy, not the MDI sensitive-entity 180-day threshold. Emergency accounts and replicated timestamps need contextual verification. | [Microsoft dormant-account guidance][accounts] |
| AD-PRIV-003 | Changed | Removed the RID-500 exemption from Schema Admins. The secured forest-root Administrator exception applies only to Enterprise Admins; Schema Admins should be empty outside active changes. | [Schema Admins][schema], [Enterprise Admins][enterprise] |
| AD-ACC-001 | Aligned | PASSWD_NOTREQD is a risky account flag; it does not prove the current password is blank. | [Microsoft account assessments][accounts] |
| AD-ACC-002 | Changed | Result wording now describes the reversible-encryption flag as configuration, not proven stored material. Historical copies and password-reset completion remain unverified. | [Microsoft account assessments][accounts] |
| AD-DOM-001 | Aligned | Zero quota limits ordinary account creation; delegated OU permissions remain valid. Zero is hardening policy, not an attribute-mandated standard. | [MachineAccountQuota semantics][quota] |
| AD-DOM-002 | Aligned | Recycle Bin improves restoration; irreversible enablement is documented. It is not a substitute for tested forest recovery backups. | [Microsoft Recycle Bin][recycle] |
| AD-DOM-003 | Changed | Corrected DFSR prerequisite wording: required for adding 2019+ DCs, not intrinsically for raising to 2016 functional level. 2016 remains a minimum product baseline; 2025 is appropriate only where the environment supports it. | [Microsoft functional levels][levels] |
| AD-CMP-001 | Changed | Absent AD expiration now returns REVIEW because hybrid devices may back up to Entra ID. Expiration alone does not prove local rotation or ACL safety. | [Microsoft LAPS join/backup options][laps] |
| AD-CMP-002 | Changed | Unrecognized OS/release evidence now returns REVIEW instead of PASS, including Windows 11 and LTSC names without a modeled date. ESU coverage and actual host freshness remain outside directory evidence. | [Windows lifecycle][lifecycle], [Windows 11 servicing][win11] |
| AD-DC-001 | Aligned | Explicit signing requirement assessed; new-versus-upgraded Server 2025 defaults remain REVIEW when unset. Registry observation does not test every actual bind path. | [Microsoft LDAP signing][ldap] |
| AD-DC-002 | Changed | Missing channel-binding setting with unknown OS now returns REVIEW instead of assuming pre-2025 defaults. Always enforcement requires client compatibility testing. | [Microsoft LDAP defaults][ldap] |
| AD-DC-003 | Aligned | Requires SMB server signing; absent registry value remains REVIEW. Client signing and SMB encryption are separate checks. | [Microsoft SMB signing][smb] |
| AD-DC-004 | Needs evidence | Known server lifecycle dates agree with published 2016/2019/2022/2025 dates; unknown OS remains REVIEW. ESU is not modeled, so FAIL describes standard lifecycle only, not proof that security updates stopped. | [2016][ws16], [2019][ws19], [2022][ws22], [2025][ws25] |
| AD-TRU-001 | Aligned | External outbound/bidirectional quarantine check has correct scope. Forest-trust SID filtering and migration exceptions are not assessed. | [Microsoft netdom trust][trust] |
| ADCS-TPL-001 | Changed | Added explicit configuration-versus-exploitability limitation. Broad enrollment plus supplied subject/authentication use remains risky; CA permissions, strong mapping and relying-party acceptance are not fully collected. | [Microsoft certificate assessments][certs] |
| ADCS-TPL-002 | Changed | Shared limitation clarifies that Any Purpose/no-EKU does not prove universal trust or successful impersonation. Template/CA authorization still matters. | [Microsoft certificate assessments][certs] |
| ADCS-TPL-003 | Needs evidence | Broad write rights align with ESC4 guidance, but template owner/custom group expansion and complete ordered effective-access evaluation are not modeled. A clean result is limited to recognized principals/ACEs. | [Microsoft certificate assessments][certs] |
| ADCS-TPL-004 | Needs evidence | Enrollment-agent exposure is meaningful; CA restrictions and newer template signature-policy requirements need evidence before claiming an exploitable chain. Existing note acknowledges restrictions. | [Microsoft certificate assessments][certs] |
| GPO-PWD-001 | Aligned | cpassword exposure remains dangerous despite old bulletin date. Confirm successful SYSVOL traversal; an empty legitimate scan is possible. Removing artifacts alone does not rotate exposed credentials. | [Microsoft MS14-025][gpp] |
| GPO-HYG-001 | Aligned | REVIEW rather than FAIL for unused GPOs correctly preserves intentional staging/rollback policies. Cross-domain/site links may need separate evidence. | [Microsoft Group Policy processing][gpo] |
| GPO-SEC-001 | Changed | Missing linked GPO now REVIEW because local/MDM policy may configure hosts. Invalid numeric values now REVIEW. Title/result say configuration rather than fleet enforcement; resultant policy and coverage are not proven. | [Microsoft policy values][lm], [processing][gpo] |
| GPO-SEC-002 | Changed | Unrecognized WDigest values now REVIEW rather than PASS. No-GPO wording no longer assumes actual host defaults. Host effective state still requires WIN-CRED-001. | [Microsoft WDigest advisory][wdigest], [processing][gpo] |
| WIN-SMB-001 | Aligned | Checks effective SMB1 server switch, not removal of the SMB1 client component. Compatibility review remains required. | [Microsoft SMB protocol guidance][smb1] |
| WIN-SMB-002 | Aligned | Requires server signing; current Windows client versus Server 2025 default distinction is retained. Does not establish outbound signing or encryption everywhere. | [Microsoft SMB signing][smb] |
| WIN-FW-001 | Aligned | All profiles and default inbound blocking assessed. Actual allow rules, active policy store and third-party equivalent controls need separate review. | [Microsoft Firewall rules][firewall] |
| WIN-RDP-001 | Aligned | NLA required when RDP enabled; disabled RDP accepted. Does not replace gateway, MFA or exposure assessment. | [Microsoft Remote Desktop][rdp] |
| WIN-LSA-001 | Needs evidence | RunAsPPL configuration is not runtime proof after reboot or with UEFI persistence. Event 12/runtime evidence needed, particularly for unset/zero values and default-enabled devices. | [Microsoft LSA protection][lsa] |
| WIN-CRED-001 | Aligned | Explicit zero or documented modern default prevents WDigest caching. Legacy patch applicability and stale memory remain outside evidence. | [Microsoft WDigest advisory][wdigest] |
| WIN-NTLM-001 | Needs evidence | Level 5 is an explicit baseline. New OS removals of NTLMv1 may make a missing legacy value insufficient to infer actual protocol acceptance; OS-specific applicability deserves dedicated follow-up. | [Microsoft policy values][lm] |
| WIN-CG-001 | Aligned | Runtime running state is used, with DC/edition exclusions. Licensing, Exchange role, hardware and previously enabled Pro downgrade exceptions are not fully collected; review contextual exceptions. | [Microsoft Credential Guard][cg] |
| WIN-PS-001 | Aligned | Script-block logging aligns with investigation guidance. Windows PowerShell and PowerShell 7 policy stores, protected logging and forwarding are separate evidence concerns. | [Microsoft PowerShell logging][ps] |
| WIN-AV-001 | Aligned | Passive/unavailable Defender leads to REVIEW, preserving third-party AV. Signatures and tamper state are additional observations, not verified equivalent protection. | [Microsoft AV coexistence][av] |
| WIN-OS-001 | Needs evidence | Windows 11 edition-specific servicing dates are distinguished; ESU/LTSC and unknown builds require individual verification. Lifecycle compliance is not patch-installation compliance. | [Windows 11 servicing][win11], [lifecycle][lifecycle] |

Validation: 246 tests passed across 11 AD/AD CS/GPO/Windows test files after the corrections. Tests include the 14/15 password boundary, Schema Admins RID-500 case, unknown LDAP defaults, unknown OS coverage and invalid GPO values. No live on-premises collection or remediation was performed.
