# On-premises collection (preview)

ConfigReview supports two collection workflows: a locally run evidence collector with browser upload, and a Windows scheduled task that uploads the same evidence over outbound HTTPS. Both use the existing AD, AD CS, GPO and Windows collectors. They never remediate configuration. Windows collection covers the machine running the collector, not every device in a domain.

The downloadable package is generated by the online web build. Follow [the collector guide](../collectors/onprem/README.txt) for installation, permissions, collection, credential rotation and local retention. The scripts and evidence packages are currently unsigned. Validate collection in an authorised lab before production use.

## Hosted setup

Set `ONPREM_ENABLED=true` only after the database owner has provisioned `aso_onprem_agents` using the definition in `apps/control-plane/src/onprem-store.ts` and granted the runtime role SELECT, INSERT and UPDATE on that table. Initialization can create the table when the runtime role has schema CREATE permission. Existing assessment and audit permissions are also required. Leave the flag unset to hide the panel and disable its routes.

Browser uploads and enrollment require the existing authenticated administrator session and same-origin mutation checks. Scheduled uploads accept a separate, randomly generated, tenant-bound upload credential. Only its hash is stored. Credentials expire in 30 days and can be revoked; no more than five active credentials are allowed per tenant. An upload credential cannot read assessments, enroll agents or call tenant connectors. Revocation is rechecked in the storage transaction.

Uploads are limited to 20 MiB compressed, 64 MiB expanded, 100 entries and 24 MiB per entry. ZIP path, compression, hash, evidence schema and secret-content validation runs before assessment. The tenant ID must match the authenticated session or registered agent. This association is declared by the uploader, not cryptographic proof of the source domain. Unknown, malformed and cloud datasets are rejected. Valid unavailable datasets remain unassessed.

The service processes at most one upload at a time per process, with a one-minute per-tenant interval. Multiple server instances require a shared quota implementation before scaling this preview. Collection is not remotely controlled. Agent code and Windows credentials remain customer-managed.

On-premises results are separate snapshots from cloud results. Consequently cloud controls in an on-premises report remain unassessed. Results follow existing 30-day retention; audit records follow 90-day retention. Local evidence remains until the administrator removes it. Expired or revoked enrollment metadata may remain until administrative cleanup.

## Validation and limitations

Automated tests cover package validation, tenant mismatch, revoked credentials, upload-only access, CSRF and unavailable evidence. A packaged synthetic replay exercises AD, AD CS, GPO and Windows and is assessed through the hosted validator. This is not live AD validation. Scheduled execution while signed out requires the customer to configure the same Windows identity in Task Scheduler and test its directory access. The installer defaults to execution while that identity is signed in.

Broader Exchange, SharePoint, Teams, Defender, Intune and Azure coverage remains a separate backlog; the on-premises collector does not close those gaps or resolve customer configuration findings automatically.
