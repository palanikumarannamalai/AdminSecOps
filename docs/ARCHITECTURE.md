# Architecture

AdminSecOps answers one question for Microsoft administrators: *"Is my Microsoft
environment secure, what have I missed, and what should I fix first?"* It does so with
a strictly separated pipeline in which **collectors collect facts, controls evaluate
facts, and the UI displays results**.

```
Microsoft environment (Entra ID, M365, Intune, Azure, AD, AD CS, GPO, Windows)
        |
        v
READ-ONLY COLLECTORS            collectors/powershell      (PowerShell 7)
        |   one JSON envelope per dataset + evidence-manifest.json (SHA-256)
        v
EVIDENCE PACKAGE (ZIP)          adminsecops-assessment-<timestamp>.zip
        |
        v
EVIDENCE INGESTION              packages/evidence
        |   safe ZIP read (in memory) -> manifest -> hash/size -> secret scan
        |   -> envelope/manifest agreement -> dataset schema validation
        v
NORMALIZED INVENTORY            packages/inventory
        |   typed Fact<T> per dataset (available | unavailable + reason)
        |   derived views: role resolution, CA analysis, licences, SPF/DMARC, NSG, AD, AD CS
        v
DETERMINISTIC CONTROL ENGINE    packages/engine + packages/controls
        |   ControlResult per control (PASS/FAIL/REVIEW/NOT_APPLICABLE/NOT_ASSESSED/ERROR)
        |   Findings (FAIL/REVIEW) with evidence references and framework mappings
        v
PRIORITIZATION                  packages/engine/src/prioritize.ts
        v
REMEDIATION / VALIDATION        control metadata (remediation, rollback, validation)
        v
DASHBOARD / REPORTS             apps/web (React), apps/api (local REST), packages/reporting
```

## Repository layout

| Path | Purpose |
|---|---|
| `packages/core` | Shared vocabulary (statuses, severities, technologies), safe JSON parsing, SHA-256, secret detection, redacting logger, errors. No dependencies. |
| `packages/schemas` | Zod schemas: evidence envelope and manifest, **every dataset contract**, control metadata, results, findings, assessment result, comparison. The single source of truth for data shapes. |
| `packages/evidence` | Reads evidence packages (ZIP in memory, or a directory), verifies the manifest, hashes and sizes, rejects secret material, validates envelopes and dataset payloads. |
| `packages/inventory` | `Inventory` (typed, read-only access to validated evidence) and pure derived views (normalization/parsing, never security judgements). |
| `packages/controls` | Control definition API (`defineControl`), shared references, and the control library under `src/library/<technology>/`. |
| `packages/engine` | Evaluation semantics, assessment orchestration, findings, prioritization, comparison, and the ZIP/directory pipeline helpers. |
| `packages/reporting` | Self-contained HTML report (no scripts, hashed-CSP) and JSON report. |
| `apps/api` | Local REST API (Fastify) bound to loopback; serves the dashboard. |
| `apps/web` | React + Vite dashboard. |
| `apps/cli` | Offline command line (`assess`, `validate`, `compare`, `controls`, `datasets`). |
| `collectors/powershell` | Read-only PowerShell 7 collector module. |
| `fixtures/assessments` | Sanitized, fictional evidence packages (generated by `scripts/build-fixtures.ts`). |
| `docs/` | Engineering documentation and ADRs (`docs/adr`). |

The requested top-level `controls/` directory was intentionally folded into
`packages/controls/src/library/<technology>/` (see [ADR-0003](adr/0003-controls-as-typed-code.md)):
controls are typed code co-located with their tests and compiled with the engine.

## Key design decisions

- **Deterministic, testable rules** ([ADR-0002](adr/0002-deterministic-controls-no-ai-verdicts.md)).
  No AI or heuristics decide PASS/FAIL. Future AI features may explain results only.
- **Evidence contract as schemas** ([ADR-0004](adr/0004-evidence-contract.md)). Collectors
  and engine share one versioned contract; unknown properties are stripped, so data that
  is not declared never reaches controls, storage or reports.
- **Missing evidence is never PASS.** Enforced centrally by `evaluateControl` and tested
  for every control by `library.test.ts`.
- **Local first** ([ADR-0005](adr/0005-local-first-processing.md)). Everything runs on the
  administrator's machine; the API refuses non-loopback binding.
- **Hosted browser mode without an API** ([ADR-0007](adr/0007-hosted-browser-mode.md),
  [HOSTED-BROWSER-MODE](HOSTED-BROWSER-MODE.md)). A static build of `apps/web` runs the
  evidence reader, engine and reporting in the visitor's browser through the
  `@adminsecops/evidence/browser` and `@adminsecops/engine/browser` entry points.
- **No composite security score** ([ADR-0006](adr/0006-no-composite-security-score.md)).
  The product reports counts, coverage (explicitly labelled as coverage) and a
  documented deterministic priority order.
- **TypeScript monorepo with npm workspaces** ([ADR-0001](adr/0001-typescript-monorepo.md)).

## Evaluation semantics (summary)

`packages/engine/src/evaluate.ts` is the only place results are produced:

1. Any required dataset unavailable -> `NOT_ASSESSED` (or `NOT_APPLICABLE` if the
   collector reported all of them as NotApplicable, e.g. licence absent).
2. `applies()` may return `NOT_APPLICABLE` (e.g. no Entra ID P2, cloud-only tenant).
3. Reading unavailable optional evidence during evaluation -> `NOT_ASSESSED`.
4. Exceptions -> `ERROR` with a generic message (a defect, not a finding).
5. `PASS` computed from Partial evidence -> `REVIEW`.
6. Result confidence can be lowered but never raised above the control's declared confidence.

See [CONTROL-MODEL.md](CONTROL-MODEL.md) for the full model.

## Extensibility for future commercial features

The data model already supports the planned paid capabilities without implementing them:

| Future capability | Foundation in place |
|---|---|
| Assessment history, drift | Stable `findingKey`, per-control results, `compareAssessments`, stored results |
| Scheduled / continuous assessment | Collector is non-interactive capable (`-SkipConnect`), deterministic engine |
| Multi-customer / MSP | `environment` identity in every manifest/result; store keyed by assessment |
| Custom controls | `defineControl` + metadata schema + registry; controls are data + pure functions |
| Hosted evidence | Ingestion is pure and in-memory; threat model covers the hosted variant |
| Team RBAC, APIs | REST API boundary already separates UI from engine |

No billing, licensing or subscription enforcement exists in this release.
